## 1. Executive Summary

Ansell Lighting is a well-established UK lighting manufacturer, founded in 1992 and supplying to more than 26 countries. The website at `ansell-lighting.com/en` serves as the primary English-language digital presence, backed by a WordPress CMS (Yoast SEO) and a Nuxt.js front-end framework. A Spanish-language variant exists at `/es/`.

The site has a strong product catalogue — 744 product pages and 74 general/landing pages — and benefits from good brand recognition and third-party distributor coverage. However, this audit identified **20 distinct SEO issues**, 6 of which are classified as critical and require immediate attention.

### Key Findings at a Glance

| Severity | Count | Examples |
|---|---|---|
| Critical | 6 | No meta descriptions, no hreflang, no schema markup, no canonical tags |
| High | 5 | Weak title tags, homepage missing brand name, utility pages indexed |
| Medium | 6 | No breadcrumbs, image alt text, font render-blocking, no FAQ schema |
| Low | 3 | Internal linking gaps, blog schema, CWV audit needed |

### Top 3 Immediate Actions

1. **Write meta descriptions** for all pages — only the homepage currently has one; all others are auto-generated by Google.
2. **Implement hreflang tags** across all pages — without these, the English and Spanish versions risk being treated as duplicate content.
3. **Add structured data (schema markup)** — the site is currently ineligible for all Google rich results including product snippets, FAQ panels, and the knowledge graph.

## 4. Technical SEO

### 4.1 Technology Stack

The site uses a **headless/decoupled architecture**: WordPress with Yoast SEO manages content on a CMS subdomain (`cms.en.ansell-lighting.com`), while Nuxt.js serves the public-facing front-end at `ansell-lighting.com`. This is a legitimate and performant pattern, but introduces specific technical SEO risks that must be actively managed (see Section 4.2).

---

### 4.2 JavaScript Rendering

**Status: Risk Identified — Verify Immediately**

During crawling, every audited page returned only CSS and JavaScript initialisation code — no rendered HTML body content, headings, or text was retrievable. This is consistent with a **Client-Side Rendered (CSR)** Nuxt.js configuration where the browser, not the server, builds the page DOM.

**Why this matters:** While Googlebot can process JavaScript, CSR pages require a second crawl pass, which delays indexing and risks content being missed entirely. If Nuxt.js is not configured for SSR (Server-Side Rendering) or SSG (Static Site Generation), the following content may be invisible to Google:

- Product names, descriptions, and specifications
- Page headings (H1, H2, H3)
- Body copy across all 818+ pages
- Internal link anchor text

**Recommendation:**
1. Open Google Search Console → URL Inspection → inspect `https://ansell-lighting.com/en/`.
2. Click **"View Tested Page"** and compare the raw HTML vs. rendered DOM.
3. If body content is absent in the raw HTML, enable SSR or SSG mode in Nuxt.js configuration.
4. Verify rendering for product pages, category pages, and application pages independently.

**Recommendations:**
- Configure Yoast SEO to output accurate `<lastmod>` timestamps for all entries.
- Exclude utility/legal pages from the sitemap (or apply `noindex` — see Section 7.4).
- Create a canonical sitemap entry at `https://ansell-lighting.com/sitemap.xml`.

### 4.5 Canonical Tags

**Status: NOT DETECTED — High Priority**

No `<link rel="canonical" />` tags were found across any audited page. Given the site's architecture — content served at `/en/` paths via a Nuxt.js front-end, with a WordPress CMS backend at a subdomain — the risk of duplicate content from multiple URL variants is significant:

- `https://ansell-lighting.com/` vs `https://ansell-lighting.com/en/`
- URLs with and without trailing slashes
- Potential CMS subdomain versions being indexed

**Recommendation:**

Add a canonical tag to every page pointing to the definitive `/en/` URL:

```html
<link rel="canonical" href="https://ansell-lighting.com/en/[page-path]/" />
```

This should be implemented via the Nuxt.js `useHead()` composable or configured within Yoast SEO's headless API output, ensuring canonical tags propagate to all 818+ pages automatically.

### 4.6 Hreflang & Multilingual SEO

**Status: NOT IMPLEMENTED — Critical**

The site serves two distinct language versions:

| Language | URL | Sitemap |
|---|---|---|
| English | `ansell-lighting.com/en/` | cms.en.ansell-lighting.com |
| Spanish | `ansell-lighting.com/es/` | cms.es.ansell-lighting.com |

No `hreflang` link attributes were detected on any audited page. This has three direct consequences:

1. **Duplicate content risk** — Google may treat `/en/` and `/es/` pages covering similar topics as duplicate content and suppress one version.
2. **Wrong language served** — Spanish-speaking users in Spain or Latin America may be served the English version, harming UX and conversion.
3. **Lost international traffic** — the Spanish version will not be surfaced to Spanish-language searchers without hreflang signals.

**Recommendation:**

Add the following to the `<head>` of every page via Nuxt.js `useHead()`:

```html
<link rel="alternate" hreflang="en" href="https://ansell-lighting.com/en/[page]/" />
<link rel="alternate" hreflang="es" href="https://ansell-lighting.com/es/[page]/" />
<link rel="alternate" hreflang="x-default" href="https://ansell-lighting.com/en/[page]/" />
```

This is a single code change in the Nuxt.js layout that will apply to all pages sitewide. The `x-default` tag indicates the English version as the fallback for unmatched locales.

**Additional considerations:**
- Confirm the Spanish version is fully human-translated, not machine-translated.
- Ensure `/es/` URL slugs mirror the `/en/` structure (e.g., `/es/about-us/` maps to `/en/about-us/`).
- Also implement hreflang in the XML sitemap as a supplementary signal.

### 5.3 Heading Structure

**Status: Unable to Verify — Action Required**

Due to JavaScript rendering, heading content (H1/H2/H3) could not be extracted from any audited page. This is a significant concern: if headings are only present in the client-side rendered DOM and not in the server-delivered HTML, Googlebot may not be reading them at all.

**Recommendations:**

4. Product pages should have H1 = product name, H2s for specification sections, features, and related products.

### 5.4 Open Graph & Social Tags

**Status: NOT DETECTED — All Audited Pages**

No Open Graph or Twitter Card meta tags were found on any page. This affects how pages appear when shared on LinkedIn, Facebook, Twitter/X, and WhatsApp — without these tags, shares will render with no image, a generic title, and no description.

**Recommendation:**

Implement sitewide Open Graph and Twitter Card tags in the Nuxt.js layout file:

```html
<!-- Open Graph -->
<meta property="og:type" content="website" />
<meta property="og:site_name" content="Ansell Lighting" />
<meta property="og:title" content="[Page Title]" />
<meta property="og:description" content="[Page Meta Description]" />
<meta property="og:image" content="https://ansell-lighting.com/images/og-default.jpg" />
<meta property="og:url" content="https://ansell-lighting.com/en/[page]/" />

<!-- Twitter Card -->
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:title" content="[Page Title]" />
<meta name="twitter:description" content="[Page Meta Description]" />
<meta name="twitter:image" content="https://ansell-lighting.com/images/og-default.jpg" />
```

For product pages, use `og:type` = `product` and supply a product-specific image. The OG image should be 1200×630px.

## 10. Core Web Vitals & Performance

**Status: Cannot Directly Measure — Risks Inferred from Tech Stack**

Direct Core Web Vitals scores could not be retrieved automatically. The following risk assessment is based on the observed technology stack.

### 10.1 Risk Assessment by Metric

| Metric | Threshold (Good) | Risk Level | Primary Cause |
|---|---|---|---|
| LCP (Largest Contentful Paint) | < 2.5s | Medium–High | JS rendering delay, custom font load, hero image loading |

| Image CLS | Add explicit `width` and `height` attributes to all `<img>` elements |
| GTM overhead | Verify GTM loads asynchronously; audit tag firing rules for unnecessary triggers |
